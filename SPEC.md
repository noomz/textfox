# Firefox Nova port

## §G

Port textfox to Firefox Nova without losing TUI appearance, existing configuration, accessibility, or browser functionality.

## §C

- Keep Nova disabled and retain README warning until support checks pass.
- Preserve existing uncommitted work and `.pi/`. Keep `NOVA-PORT.md` as investigation record.
- Target Firefox release and build per delivery path; record effective preferences and defaults. Firefox 159.0 build `20261022150525` is the investigated baseline, not proof for every path.
- Test Nova on and off while Firefox supports both. Test browser and new-tab Nova preferences independently.
- Never hard-code theme colors. Preserve `--tf-*` overrides and Firefox theme variables.
- Disposable new-tab probes may make network requests. Automation feed and widget overrides are probe-only.
- Do not delete profile files to unblock NixOS updates. Preserve old store generation and back up profile before any manual recovery; no recovery procedure is verified.
- Rootless nix-portable with proot cannot prove NixOS VM or activation behavior requiring mount namespaces or a real Nix daemon.
- `packages.default` builds locally, and home-manager activation is proven only in a disposable VM against a fetched home-manager source from the branch that pairs with the nixpkgs source (unstable `master`, not a release branch). Standalone home-manager hosts and other source pairings remain unverified.
- `Cu.reportError` output does not reach a Firefox process log, so a headless run can only assert what a refusal leaves behind, not what it says.
- `NOVA-PORT.md` contains observations, limitations, and resume commands. Temporary `/tmp` artifacts may disappear.

## §I

- I.manual: `tf-install.sh`, `tf-uninstall.sh`, `chrome/`, optional `user.js`, and user-owned `chrome/config.css`.
- I.home: `nix/modules/home-manager.nix`, Firefox profiles, generated `config.css`, and `extraConfig`.
- I.nixos: `nix/modules/nixos.nix`, `nix/pkgs/wrapTextfox.nix`, generated CSS, autoconfig, store paths, and profile restart behavior.
- I.config: `chrome/defaults.css`, `nix/modules/options.nix`, generated `configCss`, and existing `--tf-*` options.
- I.prefs: `browser.nova.enabled` and `browser.newtabpage.activity-stream.nova.enabled`, including persisted profile preferences. Managed by `user.js` block and NixOS autoconfig: `toolkit.legacyUserProfileCustomizations.stylesheets`, `svg.context-properties.content.enabled`, `layout.css.has-selector.enabled`, `widget.macos.native-context-menus`. Icon prefs `shyfox.enable.ext.mono.toolbar.icons`, `shyfox.enable.ext.mono.context.icons`, `shyfox.enable.context.menu.icons`: user-set on manual path, owned by Nix modules via `configPrefs`. `textfox.force-adopt`: NixOS opt-in, read only, never set by textfox.
- I.chrome: tabs, sidebar, toolbar, URL bar, menus, panels, findbar, split view, private windows, new-tab, and supported `about:` pages.
- I.probes: `tools/firefox-chrome/firefox-live.sh`, `ff_inspect.py`, `ff_newtab.py`, and live regression scripts.

## §V

- V1. Nova support remains unclaimed and existing disabling preference remains until UI, delivery, migration, and accessibility checks pass.
- V2. Manual, home-manager, and NixOS delivery preserve user configuration, unrelated profile files, icons, and CSS precedence. Failed or interrupted updates remain retryable without profile data loss.
- V3. Existing profiles and fresh profiles reach the intended preference state through a verified migration. Removing a preference assignment alone is not proof of migration.
- V4. Existing `--tf-*` customization continues to affect computed styles. New or renamed variables have matching defaults, Nix options, and generated `configCss` entries.
- V5. Nova and supported classic UI retain TUI styling, readable layout, visible focus, keyboard access, contrast, forced colors, reduced motion, and RTL behavior.
- V6. Browser and new-tab preference combinations are verified separately against effective values, initialized content, and real Firefox behavior. Computed styles alone do not prove visual or interaction correctness.
- V7. NixOS update safety and activation are verified against generated autoconfig and a real supported environment. Mock file APIs, Nix evaluation, and proot alone do not prove activation.
- V8. Layout tests distinguish measured behavior from estimates and cannot pass on inconclusive pseudo-element geometry or clipped content.
- V9. Regression checks cover supported delivery paths and relevant configuration options before support claims change.
- V10. A platform claim needs a headed run on that platform when the OS can draw the UI itself (native menus, OS widgets). Headless runs and computed styles cannot prove that textfox styling paints there.
- V11. A surface counts as styled only if headed painted pixels show textfox's background, border and readable text there. A rule losing to Firefox author styles, hidden under a covering layer, or blocked by a shadow boundary counts as unstyled. `about:` pages get textfox's font only (`chrome/content/about.css`): there, styled means painted text in configured font at 4.5:1; background and border stay Firefox's.
- V12. Focus and motion count as accessible only from headed proof: keyboard focus must change painted pixels around its target at 3:1 against the unfocused state (menu rows: a distinct active background), and under reduced motion no textfox transition or animation starts.
- V13. A change to a shared painted harness (`paint_display.py`, `test-surface-paint-live.py` judge) re-runs it on every platform a claim cites before that claim stands. A text check excludes only colors its surface paints as decoration.
- V14. A section title (`::before` box label) paints whole and straddles its box's top border: not clipped, not covered by other chrome, overlapping no control. Headed proof, both browser Nova states, each layout that shows it.
- V15. Firefox themes (lwtheme) are supported setups: at least Firefox's theme-picker themes. Built in: `firefox-compact-light`, `firefox-compact-dark`, `firefox-alpenglow`. AMO-hosted, installed by the picker: the 11 Nova themes (`ThemesList.sys.mjs`), each with a light and a dark variant chosen by the OS color scheme. Painted surface and title checks run with a dark and a light theme active (a Nova theme's two variants count), both browser Nova states.
- V16. Default `--tf-border` is distinguishable from `--tf-bg` as painted, in light and dark color schemes, both browser Nova states, with and without a Firefox theme.
- V17. Each textfox box paints exactly one frame: Firefox borders, outlines or shadows on a node inside a textfox box are removed where textfox draws that box's frame. Headed painted proof, both browser Nova states, active and inactive states of the box.
- V18. `--tf-container-frame` 1: the content box's border paints the color the selected tab's container line paints, and each split-view panel's border the line color of the tab it shows; a tab without a container keeps `--tf-border`. Every Firefox container color counts (blue, cyan, green, yellow, orange, red, pink, purple, violet, gray). Browser Nova off, a color textfox's palette lacks paints Firefox's `--color-<x>-40` token (cyan, violet) or, for gray, whose token Firefox defines only for Nova, `--tf-fg` as its line paints the tab's text color. 0 (default): every frame keeps `--tf-border`; only 0 and 1 are valid. Hover still paints `--tf-accent`. Headed painted proof judged against the painted tab line, both browser Nova states; option wired in `defaults.css`, `options.nix` and `configCss` (V4).
- V19. `--tf-theme-gradient` and `--tf-theme-images` (0 default, 1; only 0 and 1 valid) are split by source. Gradient 1 keeps browser Nova's own `--toolbox-background-gradient` (no Firefox theme); images 1 keeps every layer a Firefox theme ships (`--lwt-header-image`, `--lwt-additional-images`, so a Nova theme's gradients too). Both 0: painted output identical to before the options. Either on with its art present: the art paints behind the whole window (toolbox and `#browser` around content box and sidebar), animated images keep animating, and boxes over it paint a translucent `--tf-bg` scrim, not opaque `--tf-bg`; `--tf-theme-scrim` (default 80%, clamped 0%..100%) sets its strength, 100% hides the art. Each section title still hides the border line under it and paints what the box paints beside it (no B19 patch). Text over art reaches 4.5:1 against the paint under it at the default scrim. Headed painted proof, both browser Nova states, with art (image themes, a Nova theme, and the default theme's gradient) and without; option wired in `defaults.css`, `options.nix` and `configCss` (V4).
- V20. OS color scheme is a test dimension. Painted checks with a Firefox theme that has no light/dark variant (image themes) run with the OS scheme light and dark (`ui.systemUsesDarkTheme` 0 and 1). A textfox color paints from the page's or window's scheme, not from an element whose `color-scheme` Firefox resets.
- V21. textfox owns unselected tab label opacity: labels paint at opacity 1 on every platform (Firefox's macOS de-emphasis undone), and unselected label text reaches 4.5:1 as painted, with and without theme art.
